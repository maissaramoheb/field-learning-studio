# v0.5 Dark Workbench Shape

## Product Mode

Field Learning Studio v0.5 is product UI, not a landing page. The first screen must be the working evidence synthesis surface, with clear access to cases, evidence, findings, lessons, recommendations, QA review, and the learning brief.

## Users

Primary users are MEL/evaluation consultants, NGO programme teams, donor-reporting staff, learning officers, and senior reviewers. They need to inspect claims, verify evidence, check recommendations, and prepare donor-facing learning outputs under institutional quality and safeguarding expectations.

## Usage Context

Users review sensitive field evidence, trace claims across source material, check recommendations against evidence, run a human-review QA gate, and prepare donor-facing learning outputs. The interface must support careful reading and confidence in provenance rather than speed theatre or AI automation cues.

## Desired Atmosphere

The atmosphere is a premium dark analytical workspace: calm, serious, high-trust, evidence-first, and command-room oriented. It should feel like a field learning command room rather than a generic dashboard. It must not feel flashy, cyberpunk, neon, playful, or like AI magic.

## Core Product Promise

Field notes -> evidence -> findings -> recommendations -> QA -> learning brief.

The UI should make that chain visible in every major workspace. A reviewer should understand within ten seconds that the product turns field material into defensible learning outputs while preserving traceability and safety.

## Visual Metaphor

The visual metaphor is an evidence command room, analytical review desk, and field learning cockpit. The product should feel like a controlled review environment where each claim has lineage, every recommendation has a source, and the brief reads as a formal document inside the workbench.

## Anti-References

- Generic SaaS dashboard.
- Childish stepper.
- Over-rounded cards.
- Pale public-sector dashboard.
- Black background with random neon.
- Glassmorphism.
- Purple AI gradients.
- Chatbot UI.

## Design Priorities

- Strong dark page shell using deep green-black surfaces.
- Clear evidence hierarchy from observation to interpretation to linked finding.
- Traceability as the signature interaction, with compact but visibly interactive IDs.
- Document-quality learning brief preview inside the dark workspace.
- Readable cards with controlled line lengths and dark-mode contrast.
- Less clutter, fewer badges, and fewer repeated uppercase labels.
- No direct quote styling around sanitized observations.
- Responsive safety across laptop and tablet widths with no clipping or horizontal overflow.

## Command-Equivalent Workflow

Real `/impeccable` slash commands are not callable from this coding harness. The implementation will therefore follow the documented Impeccable stages manually:

1. Shape: this document defines the target product mode and design direction.
2. Layout: simplify the app shell, tabs, lessons, recommendations, drawer, and brief layout.
3. Typeset: align to a fixed product UI type scale and improve readable hierarchy.
4. Colorize: move to the requested dark restrained palette with semantic accents.
5. Distill: remove repeated labels, excessive visible metadata, and card sprawl.
6. Delight: make traceability, QA completion, selected case, and the brief preview feel memorable without decoration.
7. Harden: check overflow, focus states, contrast, drawer scroll, and responsive behavior.
8. Critique: run detector and manual browser review against the primary user path.
9. Polish: resolve validation and final visual inconsistencies before commit.
