# v0.6 Blue Command Workbench Refinement

## 1. Assessment of v0.5 Screenshots / Preview

The v0.5 dark workbench is directionally stronger than the earlier light dashboard because the product now feels like a focused analytical workspace rather than a generic institutional web page. The dark shell, tabbed workbench, case selector, evidence cards, QA gate, traceability drawer, and brief preview all support the core evidence-to-learning workflow.

The remaining issue is visual identity. The current palette reads as green-black with teal trace accents, which makes the app feel closer to a terminal, operations console, or security dashboard than a premium field learning synthesis tool. The first screen has good structure, but the active case panel and pathway cards still read as dark data cards rather than a calmer case intelligence panel. Traceability is functional and visible, but it should feel more like the signature inspection layer.

## 2. Why v0.5 Is Better But Still Not Acceptable

v0.5 is better because it preserves the product architecture while improving hierarchy, safety framing, and traceability. It removes the older pale dashboard feel and gives users a serious review environment.

It is not yet acceptable because:

- The green/teal palette dominates too much of the product mood.
- Primary action, traceability, selected case, and active navigation are too visually close to each other.
- Traceability IDs are useful but can still feel like small metadata tags rather than a defensible claim lineage system.
- Some cards are dense and boxy, especially evidence, findings, lessons, recommendations, and QA cards.
- Typography is readable but can be slightly more executive and less terminal-like.
- The brief preview should stand out more as a donor-facing document inside the dark workbench.

## 3. Blue-Slate Visual Direction

v0.6 should move toward a blue-black analytical evidence command center: serious, calm, premium, institutional, donor-safe, and evidence-first. The dark direction remains, but the mood shifts from green operations room to blue-slate review workspace.

The product should feel like a night-mode executive analysis tool for inspecting field evidence, not a hacker console, security dashboard, neon cyberpunk interface, or generic dark SaaS app.

## 4. Color System Changes

The color system will move to:

- Main background: `#050B14` / `#07111F`.
- Secondary background: `#0B1625`.
- Primary surface: `#101B2C`.
- Elevated surface: `#162338`.
- Soft surface: `#1D2B42`.
- Border: `rgba(148, 163, 184, 0.22)`.
- Text primary: `#F8FAFC`.
- Text secondary: `#CBD5E1`.
- Text muted: `#94A3B8`.
- Primary action: `#2563EB`.
- Primary action hover: `#3B82F6`.
- Traceability accent: `#22D3EE` / `#38BDF8`.
- Traceability soft: `rgba(34, 211, 238, 0.10)`.
- Amber: `#F59E0B`, reserved for safety and needs-review notes.
- Red: `#F87171`, reserved for warnings and risk.
- Green: `#34D399`, reserved only for pass/success states.

Primary blue will carry selected navigation and main actions. Cyan will be used mainly for traceability and focus states. Amber will remain safety-specific. Green will be limited to pass states.

## 5. Typography Refinements

The existing system sans stack remains because this is product UI and readability matters more than decorative font pairing. Refinements will focus on:

- Slightly calmer headline scale and line-height.
- Less dominant uppercase metadata.
- Smaller, quieter ID badges when they are secondary.
- Stronger body line-height in explanatory panels.
- More editorial section headings without marketing-style hero excess.
- Preserved monospaced IDs for traceability.

## 6. Component-Level Improvements

The implementation will refine existing components rather than introduce new UI libraries:

- App shell: blue-black surfaces, reduced green tint, calmer background wash.
- Header: v0.6 labeling, stronger premium case intelligence panel, more deliberate transformation path.
- Case selector: selected state becomes blue/cyan with reduced border intensity; School Nutrition safety note stays amber.
- Tabs: active state uses primary blue, hover states use slate surfaces, focus remains cyan.
- Cards: reduce repeated border noise and improve contrast between base and elevated surfaces.
- Evidence cards: make `Inspect Chain` more visually important than low-priority metadata.
- Findings: keep contradiction callouts amber but reduce glow and density.
- Lessons / Good Practices: improve spacing and avoid clipping at laptop/tablet widths.
- Recommendations: preserve vertical priority grouping while making owner/timeframe/risk/success fields easier to scan.
- QA Review: use semantic blue-slate surfaces, with green only for pass, amber for needs review, and red for warnings.
- Brief: keep a light paper canvas inside the dark workspace and make raw Markdown secondary.

## 7. Traceability Enhancement Plan

Traceability is the product signature. v0.6 will strengthen:

- `TraceButton` styling so IDs remain calm but clearly interactive.
- `TraceChain` presentation so it reads as a source-to-brief lineage, not just a row of tags.
- Active trace state with cyan emphasis and slate supporting nodes.
- Drawer header and source-to-brief path panel.
- Evidence -> finding -> recommendation -> QA -> brief relationship in cards.
- `Inspect Chain` action prominence in Evidence cards.

The desired interaction feeling is: every claim can be inspected and defended.

## 8. Screen-by-Screen Refinement Plan

Hero / first screen:
- Keep dark mode.
- Shift shell and hero from green-black to blue-black.
- Reframe active case as a case intelligence panel.
- Make the transformation path calmer and more deliberate.

Case selector:
- Keep compact pathway cards.
- Move selected state to blue/cyan.
- Lower border intensity.
- Keep the School Nutrition safety note amber and refined.

Overview:
- Preserve the review path, workflow, sandbox, evidence base, and traceability path.
- Make Evidence Base and Signature Traceability panels less boxy.
- Keep sandbox warning clear without making it visually heavy.

Evidence:
- Keep no quote styling around sanitized observations.
- Improve scannability.
- Make `Inspect Chain` more important than metadata.
- Calm ID badge styling and reduce repeated borders.

Findings:
- Keep `No finding without evidence`.
- Reduce dense-card feeling.
- Keep contradictory evidence amber but quieter.
- Improve visible claim lineage.

Lessons:
- Maintain no clipping or horizontal overflow.
- Improve spacing between lesson statements, details, and evidence IDs.
- Separate lessons and good practices more elegantly.

Recommendations:
- Keep grouped vertical sections.
- Improve executive readability.
- Reduce unnecessary card height.
- Make owner/timeframe/risk/success indicators easier to scan.

QA Review:
- Keep review gate concept.
- Use blue-slate surfaces.
- Preserve deterministic, non-AI language.
- Use green only for pass, amber for needs review, red for warnings.

Brief:
- Make document preview stand out more against the dark shell.
- Preserve light paper canvas.
- Keep raw Markdown secondary and copyable.
