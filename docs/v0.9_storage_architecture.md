# v0.9 Storage Architecture & Persistence Foundation

## 1. Overview

Field Learning Studio v0.9 introduces a **local-first, normalized IndexedDB persistence foundation** designed for field researchers, evaluators, and consultants. It transitions the application from a read-only demonstrator into a persistent local workspace that maintains strict study isolation, relational integrity, and defensible auditability.

---

## 2. IndexedDB Schema Specification

- **Database Name**: `FieldLearningStudioDB`
- **Database Version**: `1`
- **Driver**: `idb` (native Promise-based wrapper around IndexedDB)

### Normalized Object Stores

| Store Name | Key Path | Primary Key Type | Indexes | Description |
|---|---|---|---|---|
| `studies` | `"id"` | `StudyId` (string) | `by_status`, `by_updatedAt` | Study-level metadata, scope configuration, and lifecycle status. |
| `sources` | `["studyId", "id"]` | `[string, string]` | `by_study`, `by_date` | Primary collection sources (interviews, FGDs, observations, documents). |
| `evidence` | `["studyId", "id"]` | `[string, string]` | `by_study`, `by_source`, `by_validationStatus` | Atomic evidence entries tagged by theme, strength, and status. |
| `debriefs` | `["studyId", "id"]` | `[string, string]` | `by_study`, `by_date` | Daily Field Debriefs recording team impressions across one or more sites. |
| `findings` | `["studyId", "id"]` | `[string, string]` | `by_study`, `by_validationStatus` | Evaluative findings supported by evidence chains. |
| `lessons` | `["studyId", "id"]` | `[string, string]` | `by_study`, `by_validationStatus` | Actionable lessons with contextual preconditions and transferability. |
| `goodPractices` | `["studyId", "id"]` | `[string, string]` | `by_study`, `by_validationStatus` | Proven practices with replication criteria and risk boundaries. |
| `recommendations` | `["studyId", "id"]` | `[string, string]` | `by_study`, `by_finding`, `by_validationStatus` | Defensible recommendations tied to specific findings and actors. |

## 3. Source-of-Truth Rule

1. **Normalized IndexedDB is the authoritative persistence layer**:
   Individual entity records stored in normalized object stores represent the definitive state of truth.
2. **`FieldStudy` is an assembled projection**:
   `assembleStudy(studyId)` generates a non-authoritative read model for consumption by the UI, exports, and sensemaking engines. Changes to study data are written through the repository boundary to normalized stores, not by serializing monolithic study documents.

---

## 4. Compound Key Strategy

- All child entities use compound primary keys: `keyPath: ["studyId", "id"]`.
- **Key Isolation**: A human-readable identifier (such as `EV-001` or `SRC-001`) can exist concurrently in multiple studies (e.g., `["study-alpha", "EV-001"]` and `["study-beta", "EV-001"]`) with zero risk of key collisions or data leakage.
- **Index Scoping**: Index `by_study` on every child store allows high-speed retrieval of all records belonging to a study via `getAllFromIndex(storeName, "by_study", studyId)`.

---

## 5. Demo Template Strategy (Option A)

- **Pristine Read-Only Templates**:
  `community-bridges` and `school-nutrition` remain untouched static fixtures in `src/data/cases/`.
- **Idempotent Bootstrapping**:
  `bootstrapDemoTemplates()` checks whether the demo studies already exist in `studies`. If present, it skips them; if absent, it seeds them into IndexedDB with `isDemoCase: true`. Repeated calls never create duplicate records.
- **Guard Against Deletion**:
  `deleteStudy(studyId)` explicitly rejects attempts to delete demo templates (`isDemoCase: true`).
- **Cloning to Editable Copies**:
  `cloneDemoStudy(sourceStudyId, newTitle?)` produces an independent editable copy with:
  - a newly generated UUID `studyId` (e.g., `study-m...`)
  - `isDemoCase: false`
  - all child entities cloned with `studyId` remapped to the new UUID
  - original internal human-readable IDs (`EV-001`, `FND-001`) and relational links preserved intact.

## 6. Portable `.fls.json` Backup Architecture

Field Learning Studio uses an unencrypted JSON envelope format for backup, transfer, and archival.

### Envelope Structure

```json
{
  "format": "field-learning-studio-backup",
  "version": 1,
  "exportedAt": 1717200000000,
  "warning": "WARNING: This export contains unencrypted field study records. Ensure this file is stored securely and handled in accordance with participant consent, data protection regulations, and institutional ethics protocols.",
  "study": { ... },
  "sources": [ ... ],
  "evidence": [ ... ],
  "debriefs": [ ... ],
  "findings": [ ... ],
  "lessons": [ ... ],
  "goodPractices": [ ... ],
  "recommendations": [ ... ]
}
```

### Safety and Transactional Integrity

- **Pure Runtime Validator**:
  `validateStudyBackupEnvelope(data)` strictly verifies format identifier, version, timestamp, warning banner, study metadata, and child entity array shapes prior to database interactions.
- **Atomic Import Transactions**:
  `importStudyBackup(json, strategy)` executes all writes inside a single IndexedDB transaction across all 8 stores. If any record fails validation or insertion, the entire transaction rolls back, preventing partial data corruption.
- **Import Strategies**:
  - `reject_collision`: Rejects with an error if a study with the same `studyId` already exists.
  - `overwrite`: In a single transaction, deletes previous records for this `studyId` and replaces them with imported data.
  - `import_as_new`: Generates a fresh `studyId`, appends `(Imported)` to the title, and remaps all child records while preserving internal cross-references.

## 7. Compatibility Boundary: v0.8 Fixtures & v0.9 Persistence

- **Zero-Regression Design**:
  Existing UI components and export pipelines consume `DemoCase` without modification during Phase 1.
- **Bidirectional Adapters (`demoStudyAdapter.ts`)**:
  - `adaptDemoCaseToFieldStudy(demoCase: DemoCase): FieldStudy`: maps legacy fixture schemas to normalized v0.9 domain models with default validation status (`Validated`), revision counts, and derived study scope.
  - `adaptFieldStudyToDemoCase(study: FieldStudy): DemoCase`: projects an assembled `FieldStudy` back to a `DemoCase` shape for any legacy consumer.
- **Preserved Test Harness**:
  All 27 Phase 0 characterization tests (traceability, export boundaries, QA rules, PII sanitization) remain 100% green.
